PRESENÇA IFBA — INTEGRAÇÃO DE EVENTOS E FORMULÁRIOS COM SUPABASE
================================================================

O QUE ESTA VERSÃO ALTERA
- O login administrativo continua usando Supabase Auth e a autorização via public.is_admin().
- Eventos são gravados e carregados da tabela public.events.
- A configuração dinâmica do formulário é armazenada no campo JSONB form_config.
- O link público usa o UUID do evento e consulta o Supabase, em vez de procurar o evento no localStorage do celular.
- As respostas são gravadas em public.form_responses e podem ser consultadas pelo painel administrativo.
- Ativar/desativar eventos atualiza public.events.

ARQUIVOS
- index.html: estrutura do site.
- app.js: funcionalidades e integração com Supabase.
- style.css: identidade visual.
- config.js: URL do projeto e chave pública publishable.
- supabase.sql: script SQL preexistente do projeto; não é necessário executá-lo novamente apenas para esta atualização.

PUBLICAÇÃO
1. Faça backup dos arquivos atuais do repositório.
2. Extraia este ZIP.
3. Envie o CONTEÚDO desta pasta para a raiz publicada do repositório GitHub Pages, substituindo os arquivos correspondentes.
4. Faça Commit changes.
5. Aguarde o GitHub Pages publicar e recarregue o site.
6. Entre no painel com a conta administrativa já cadastrada.
7. Crie um NOVO evento de teste e clique em “Gerar formulário + QR Code”.
8. Abra o link em outro celular, preferencialmente em uma janela anônima, e teste o envio.

IMPORTANTE SOBRE EVENTOS ANTIGOS
Os eventos criados pela versão demonstrativa anterior estão guardados apenas no localStorage do navegador que os criou. Eles não são transferidos automaticamente para o banco. Depois de publicar esta versão, será necessário recriar esses eventos no painel para gerar novos links compartilháveis. Os links antigos não serão convertidos automaticamente.

LIMITAÇÕES QUE AINDA EXIGEM ETAPA PRÓPRIA
- A validação de GPS ainda acontece no navegador. Ela NÃO é uma validação segura no servidor e pode ser falsificada; não use isso como controle antifraude até implementar RPC/Edge Function com validação no backend.
- Banners são mantidos no campo image_url como conteúdo já carregado; para uso institucional, recomenda-se migrar imagens para Supabase Storage.
- Não foi possível testar uma gravação real no projeto Supabase a partir deste ambiente. A integração foi revisada estaticamente, mas precisa do teste de ponta a ponta descrito acima.

SEGURANÇA
- config.js contém somente a chave pública publishable, apropriada para o navegador.
- Nunca inserir chave secret ou service_role no site.
